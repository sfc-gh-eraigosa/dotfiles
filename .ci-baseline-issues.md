# CI lint baseline — backlog for follow-up phases

Snapshot taken on the branch that introduced the lint Makefile target
(GitHub issue #46, phase 1). The CI `lint` job will fail on these
counts until phases 2+ chip away at them. Until the backlog clears,
the workflow exits non-zero — this is intentional: the baseline IS the
work that follow-up phases need to do.

If you're a future contributor adding a feature, do NOT bypass these
warnings with `// nolint`, `# shellcheck disable=...`, or
`<!-- markdownlint-disable -->` blocks except where the rule is
genuinely wrong for the situation (cite the reason in a one-line
comment alongside the disable).

## Markdown — `make lint-markdown`

markdownlint-cli2 **0.22.1** (markdownlint 0.40.0): **~979 findings**
across 57 files.

Dominant rule violations (by symptom):

- **MD022** — blanks-around-headings (missing blank line above/below `### Heading`)
- **MD032** — blanks-around-lists (missing blank line before bulleted lists)
- **MD031** — blanks-around-fences (missing blank line around ```code``` fences)
- **MD009** — trailing whitespace (single-space, not the two-space line break)
- **MD040** — fenced-code-language (```code without a language tag)
- **MD036** — emphasis-as-heading (`**Bold Title**` used instead of `#### Title`)

These are mostly cosmetic — no rule violation reflects content correctness.
Phase 2 of issue #46 should auto-fix MD009 + MD022 + MD031 + MD032 + MD040
in a single pass with `markdownlint-cli2 --fix`.

`MD013` (line-length) is disabled repo-wide via `.markdownlint.jsonc` —
do not re-enable without a discussion. Our CLAUDE.md prose is intentionally
long-form.
