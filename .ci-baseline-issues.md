# CI lint baseline — backlog for follow-up phases

Snapshot taken on the branch that introduced the lint Makefile target
(GitHub issue #46, phase 1). These counts are the backlog that phases 2+
chip away at.

**Gate status: WARN-ONLY.** Running `make lint` locally still reports
every finding below (non-zero exit), but in CI the lint steps are
`continue-on-error: true` and the coverage gate runs with
`COVERAGE_ENFORCE=0` — so the lint job and unit-tests job stay GREEN
despite the backlog. This is deliberate: a required check that is
permanently red would deadlock the phase-6 merge queue (nothing, not even
this PR, could ever land). As each category below reaches zero, the
corresponding warn-only flag should be dropped so the gate becomes strict
(see the per-step note in `.github/workflows/docker-image.yml` and
`COVERAGE_ENFORCE` in `scripts/test.sh`).

If you're a future contributor adding a feature, do NOT bypass these
warnings with `// nolint`, `# shellcheck disable=...`, or
`<!-- markdownlint-disable -->` blocks except where the rule is
genuinely wrong for the situation (cite the reason in a one-line
comment alongside the disable).

### Phase 5 scope expansion: `opt/profiles/`

Phase 5 (issue #46) extended `make lint-shell` to cover the user-facing
shell entrypoints in `opt/profiles/` (`.bashrc`, `.profile`,
`.bash_aliases`, `.bash_logout`, `.docker.sh`, `.goenv.sh`,
`.nano_profile`, `.xsessionrc`). This added **~21 warnings** to the
baseline (69 → 90). No single SC code dominates the increase, so we
followed option (b) from the issue plan: document the delta and accept
the higher baseline rather than silence specific codes. Backfill should
target the broad ones first:

- **SC2148** (missing shebang) — +7. Dotfile profiles intentionally have
  no shebang because they're sourced, not executed. Add a `# shellcheck
  shell=bash` directive at the top of each instead.
- **SC2155** (declare/assign masking) — +5. Real bug class; fix by
  splitting `local foo=$(cmd)` into `local foo; foo=$(cmd)`.
- **SC2142** (aliases can't use positional params) — +2, both in
  `.bash_aliases` (`novassh`, `novassh1`). Convert to functions; the
  current alias-of-a-function trick already half-acknowledges this.

`.zshrc` is **intentionally excluded** from `make lint-shell`: shellcheck
does not support zsh and emits SC1071 (error) on first parse, which
would fail the whole job regardless of `-S warning`. A future
`make lint-zsh` target could shell out to `zsh -n` for syntax-only
validation, but no existing OSI-permissive linter handles zsh semantics
the way shellcheck does for bash. Deferred until there's a real
zsh-only bug to motivate the work.

## Go coverage — `scripts/test.sh unit` (phase 3)

Phase 3 of issue #46 introduces per-module coverage gating in
`scripts/test.sh`. The thresholds are declared at the top of the script
in the `COVERAGE_MIN` associative array. Per the issue plan the planned
floors are: **gss=70, tmux-mgr=60, gsl=60, wol=60**.

The target floors are on from day one, but enforcement is **warn-only**
while `COVERAGE_ENFORCE=0` (the current default in `scripts/test.sh`):
modules under their floor print a WARN line so the gap stays visible, but
CI stays green so the merge queue isn't deadlocked by the pre-existing
gap. Backfill issues #50 (tmux-mgr) and #51 (wol) track clearing it; once
both modules clear 60%, flip `COVERAGE_ENFORCE` to default `1` to make the
gate strict.

Coverage measured at the time the gate landed:

| Module       | Coverage | Threshold | Status |
|--------------|---------:|----------:|--------|
| `src/gss`    |   80.5%  |       70% | PASS   |
| `sdk/gsl`    |   88.7%  |       60% | PASS   |
| `src/tmux-mgr` | 48.8%  |       60% | **FAIL** (gap: 11.2pp) |
| `sdk/wol`    |   55.6%  |       60% | **FAIL** (gap: 4.4pp)  |

Backfill targets (file follow-up PRs to clear the failures):

- **`src/tmux-mgr`**: drag is `cmd/` at 34.1% coverage. The two
  `pkg/agent` (83.4%) and `pkg/tmux` (81.0%) packages are healthy.
  Add tests for the cobra command handlers in `cmd/` to clear the gap.
- **`sdk/wol`**: drag is `cmd/` at 9.4% coverage; it's almost entirely
  the main CLI plumbing. Add tests for argument parsing + the magic-packet
  builder so coverage clears 60%.

When a module clears its threshold, raise `COVERAGE_MIN[<mod>]` to the
next sensible floor (typically the planned value, then ratchet upward
when the suite stabilises further). Modules absent from `COVERAGE_MIN`
are warned (not failed) so new modules can land before their tests are
ready to gate.
