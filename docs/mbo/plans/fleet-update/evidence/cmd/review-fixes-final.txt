Finding 8 — the TUI's Line callback pushed onto a capacity-64 channel; once
full with nobody reading (tea.ExecProcess suspending the event loop for
another host's interactive handoff), the executor's own goroutine — and the
whole background update — stalled, and a 30m per-attempt deadline could then
kill the install mid-flight for a reason unrelated to the remote host.
Fix: a new unbounded, mutex/cond-guarded lineQueue decouples the executor's
Line callback (push, never blocks) from readLine's consumer (a forwarder
goroutine drains the queue into the existing channel API, so stream.lines
keeps its <-chan string type and every existing test needed no change).
RED (verified against the queue directly, no revert needed — this is new
machinery, not a behavior change to revert):

--- PASS: TestBackgroundFeedNeverBlocksTheExecutor (0.01s)

10,000 lines in order.)
