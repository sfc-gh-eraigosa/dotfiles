Findings closed (test name -> one-line fix):

1. TestResetInMultiAndDefaultFormsTargetsOriginB1NotFetchHead /
   TestResetInSingleBranchFormKeepsFetchHead
   -> ResetScript now takes (checkoutRef, resetTo); multi/default forms
      pass "origin/$b1" instead of the always-FETCH_HEAD.

2. TestDefaultSyncFetchStaysInTheAndChain / TestDefaultSyncFailsWhenFetchFails
   -> the default-form body wraps branch-resolution in `{ ... }` chained
      with `&&` right after `git fetch origin`, so a failed fetch now stops
      the whole chain instead of falling through via `;`.

3. TestCarryNotesSurviveARetry
   -> runWithRetry accumulates every attempt's parsed notes (allNotes) in
      order instead of keeping only the last attempt's; armAndMaybeRestoreNow
      now takes the FIRST "orig=" note rather than the last, so a later
      attempt's "orig=<target>" (already switched by an earlier attempt)
      cannot clobber the operator's true original branch.

4. TestRescueRecordsOrigViaSymbolicRefNotAbbrevRef / TestRescueCommitToleratesNothingToCommit
   -> RescueScript records orig via `git symbolic-ref -q --short HEAD ||
      git rev-parse HEAD` (not --abbrev-ref, which prints "HEAD" verbatim
      when detached) and wraps its commit in `|| true`, mirroring
      ResetScript.

5. TestRestoreFalseLeavesHostOnTarget (rewritten to pin the CORRECT
   behaviour — it previously asserted the buggy Skipped-restore-Result
   shape) / TestDisabledRestoreDoesNotFailTheHost
   -> fireDueRestores/armAndMaybeRestoreNow synthesize NO "<repo>.restore"
      Result at all when restore is disabled; the fact is recorded as a
      note on the sync step's own Result instead, via noteRestoreDisabled.

6. TestNoRestoreIsHonouredWhenTheSyncFails
   -> armAndMaybeRestoreNow's immediate (sync-failed) path now also
      consults restoreDisabled(repo) before calling runRestore, matching
      the deferred path.

7. TestExtrasLoopTracksFailureAcrossIterations / TestExtrasFailureFailsTheStepEvenWhenALaterExtraSucceeds
   -> extrasScript tracks a `fail` flag across the loop (`|| fail=1` on
      each mutating command, `[ "$fail" = 0 ]` as the loop's own exit),
      since POSIX `for`'s exit status is only its last iteration's.

8. TestInteractiveDeadlineKillsTheChild / TestInteractiveWithoutCtxRunnerRunsUnboundedAndNotes
   -> Console.Interactive no longer races a goroutine against time.After;
      it type-asserts the runner for the new (updexec-local)
      interactiveCtxRunner interface and calls RunInteractiveCtx (added to
      runner.Exec via exec.CommandContext + WaitDelay, and to runner.Fake)
      when available, else runs unbounded.

9. TestJitterDefaultsToRandomnessWhenRandIsNil
   -> Executor.rand() defaults to math/rand/v2's Float64 when Rand is nil,
      matching the field's doc comment (previously nil was passed straight
      through to Backoff.Wait, which treats nil as the constant midpoint —
      no jitter movement at all in production).

10. TestASuccessfulAttemptIsNeverReportedAsTimedOut
    -> timedOut is now `callErr != nil && timeout > 0 &&
       errors.Is(ctx.Err(), DeadlineExceeded)` — a call that returned nil
       error is never timed out, regardless of ctx.Err() by the time it
       returns (closes the output-drain-window race the finding describes).
