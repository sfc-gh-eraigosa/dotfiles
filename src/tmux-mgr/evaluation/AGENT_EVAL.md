# Evaluation: Agent Orchestration

This document provides instructions for evaluating the `tmux-mgr` Hybrid Agent Orchestration feature.

## Goal
Prove that the agent can successfully:
1.  **Route** to `tmux-mgr agent` commands.
2.  **Spawn** multiple agents into isolated Git worktrees/tmux panes.
3.  **Coordinate** using native Gemini tracker IDs.
4.  **Fan-In** detailed findings from `RESULT.md`.
5.  **Cleanup** the isolated environments.

## Evaluation Steps (Verification Script)

To evaluate the skill, the coordinating agent must execute the following sequence:

### 1. Planning (Native)
Use `tracker_create_task` to create two distinct "Hello World" tasks.
-   **Task 1**: "Agent A: Write 'Hello from Agent A' to RESULT.md and exit."
-   **Task 2**: "Agent B: Write 'Hello from Agent B' to RESULT.md and exit."

### 2. Execution (Isolation)
Spawn the agents using `tmux-mgr`:
```bash
tmux-mgr agent start generalist --task-id <id_from_task_1>
tmux-mgr agent start generalist --task-id <id_from_task_2>
```

### 3. Monitoring
Check the status of the physical sessions:
```bash
tmux-mgr agent list
```
Verify that two sessions are listed and that their `WorktreePath` exists in `~/.config/tmux-mgr/worktrees/`.

### 4. Results (Fan-In)
Wait for the sub-agents to finish (or manually check if `RESULT.md` is populated in their worktrees). Retrieve the results:
```bash
tmux-mgr agent complete <session_id_1>
tmux-mgr agent complete <session_id_2>
```

### 5. Finalization & Cleanup
Confirm that the results match the expectations ("Hello from Agent A/B").
Cleanup the sessions:
```bash
tmux-mgr agent cleanup <session_id_1>
tmux-mgr agent cleanup <session_id_2>
```

## Success Criteria
- [ ] Tmux window split twice (creating two new panes).
- [ ] Git worktrees created for each session.
- [ ] `RESULT.md` files generated by sub-agents.
- [ ] Primary agent retrieves and summarizes the "Hello World" outputs.
- [ ] Worktrees and tracking JSONs are removed after cleanup.
